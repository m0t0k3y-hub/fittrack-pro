## 1. アプリケーション概要

* **目的:** トレーニング内容（予定・実績）および体組成データの記録・可視化による継続支援
* **対象環境:** レスポンシブ対応Webアプリケーション（スマートフォン操作を主想定）

---

## 2. 機能要件

### ユーザー管理機能

* **新規登録 / ログイン / ログアウト:** メールアドレス・パスワード認証
* **プロフィール設定:** ニックネーム、身長（初期値設定）

### トレーニング管理機能

* **カレンダー表示:**
* 月単位のカレンダー表示
* 日ごとに「予定あり（未完了）」「実績あり（完了）」のバッジ表示


* **種目マスタ管理:**
* デフォルトの部位別種目（胸：ベンチプレス、背中：デッドリフト 等）
* ユーザー独自のカスタム種目追加


* **予定・実績の記録:**
* ステータス切替（「予定」⇄「実績」）
* 種目ごとに `重量(kg)` × `レップ数(回)` × `セット数` の入力
* メモ機能（インターバル時間やコンディションなど）



### 身体計測管理機能

* **身体データの記録:** 日別の体重(kg)、体脂肪率(%)の入力（身長は基本固定、更新可能）

### ダッシュボード・グラフ機能

* **推移グラフ表示:**
* **体組成グラフ:** 体重・体脂肪率の折れ線グラフ（期間：1週間 / 1ヶ月 / 3ヶ月 / 全期間）
* **筋トレ実績グラフ:** 特定種目の「最大挙上重量（MAX）」または「総負荷量（重量×回数×セット）」の推移



---

## 3. 非機能要件

* **モバイル最適化（UI/UX）:** ジム内での片手入力、数値入力キーボード（テンキー）の自動立ち上げ
* **セキュリティ:** ユーザーごとのデータ完全分離（他ユーザーの記録の非公開）
* **レスポンス速度:** 日次記録の保存・呼出が1秒未満で完了すること

---

## 4. データモデル設計（主要テーブル構成案）

| テーブル名 | 主なカラム | 説明 |
| --- | --- | --- |
| **users** | `id`, `email`, `password_hash`, `height`, `created_at` | ユーザー情報 |
| **exercises** | `id`, `user_id` (NULL可), `name`, `target_muscle` | 種目（共通＋カスタム） |
| **workout_logs** | `id`, `user_id`, `date`, `status` (予定/実績), `memo` | 1日単位の筋トレヘッダー |
| **workout_sets** | `id`, `workout_log_id`, `exercise_id`, `set_order`, `weight`, `reps` | セット詳細 |
| **body_metrics** | `id`, `user_id`, `date`, `weight`, `body_fat_percentage` | 体組成データ |

## 5. 推奨技術スタック例
* **githubリポジトリ:** https://github.com/m0t0k3y-hub/fittrack-pro.git
* **フロントエンド:** Next.js (React) + Tailwind CSS + shadcn/ui（UIコンポーネント）
* **グラフライブラリ:** Recharts または Chart.js
* **バックエンド / DB:** Supabase（PostgreSQL + 認証機能を即座に構築可能）
* **ホスティング:** Vercel
